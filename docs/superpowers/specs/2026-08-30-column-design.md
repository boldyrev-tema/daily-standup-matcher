# Колонка (шаг 3, вторая половина) — design

## Что строим

Последнее из трёх канонических размещений по техспеке заказчика («Колонка и второй экран — те же данные, другая вёрстка по шаблонам»). «Второй экран» уже сдан; «Колонка» — узкое вертикальное размещение поверх окна звонка (в реальном продукте `live_copilot_poc`-суфлёр 400×880, тот же прецедент ширины).

Сверено с первоисточником перед проектированием (не с пересказом в памяти) — реальный макет `bold-rain-4095` открыт через Playwright, прогнан до конца кнопкой «Начать», проверены все три фазы (`before`/`live`/`after`).

Данные и вся логика узнавания — те же, что во «втором экране», без изменений. Это чисто новый шаблон поверх уже готового `Meeting`-состояния, как и предполагалось в записи по завершении «Полосы».

## Что нового по сравнению со «вторым экраном»

### Вертикальная раскладка вместо трёх колонок

Порядок сверху вниз (подтверждён на макете, отличается от порядка «слева направо» второго экрана): **шапка → Подсказываю → Записал → Слышу**.

### Шапка — новый элемент, которого не было ни в «Полосе», ни во «втором экране»

На макете: заголовок встречи (у заказчика — «Дейлик CRM 2.0», реальные данные его демо, не переносим) + строка состояния, которая меняется по фазам:
- `before` — «Сегодня, 12:00» (тот же статичный текст, что уже используется в `polosa.html`).
- `live` — зелёная живая точка + прошедшее время **в минутах без секунд** (`"1 мин"`, не `M:SS` как в «Полосе» — на макете подтверждено именно так).
- `after` — «Закончился · обсудили N из M», где N = `agenda.done.length`, M = `agenda.done.length + agenda.remaining.length`.

Кнопка «Начать»/«Сначала» на макете декоративная (управляет демо-проигрыванием MagicPath) — в наших реплеях ни один из существующих шаблонов (`polosa.html`, `second_screen.html`) не вешает на неё обработчик, реплей всегда автостартует из Python. В «Колонке» кнопку не добавляем вовсе — не несёт функции, только фаза/текст шапки.

Никаких новых полей в `Meeting`/`_state_json` не требуется — оба значения (N, M, прошедшее время) уже целиком выводимы из существующих `state.phase`, `state.elapsed_s`, `state.agenda.done`, `state.agenda.remaining`.

### Слышу — последние 3 реплики, не полный скролл

На макете колонка «Слышу» внизу показывает ровно 3 последние реплики (проверено на разных стадиях демо — как только появляется 4-я, самая старая исчезает), без прокрутки. Это единственное сокращение данных по сравнению со «вторым экраном» (там — полный скролл всей истории). Подчёркивание `hit_words` и суффикс «→ KEY» — переносятся как есть.

### Записал / Подсказываю — без изменений по содержанию

Те же секции/переходы по фазам, что и во «втором экране» (`agenda_row()`, тревожная строка, все 5 фактов, прогрессивное «Сказали», «Спроси»). Разница только в том, что они уложены друг под другом, а не в отдельных колонках.

## Реализация

`column.html` + `run_column.py`. Слой данных (`_state_json`, `_primary_match`, `TEAM`, `GROQ_KEY_PATH`) не дублируется — `run_column.py` импортирует всё это напрямую из `run_second_screen.py` (state-контракт идентичен, дублирование того же кода было бы риском разъехаться при следующем фиксе, как уже случалось с багом матчера, чинившимся отдельно в «Полосе» и «втором экране»). Единственная новая Python-обвязка — тот же цикл реплея, что и в `run_second_screen.py`, но с другим HTML-файлом/заголовком/размером окна (400×880, по прецеденту `live_copilot_poc`).

Рендер-функции в `column.html` (`renderHeard`, `buildAgendaRow`, `buildAgendaSection`, `renderRecorded`, `renderHints`) — перенесены из `second_screen.html` без изменений логики, кроме `renderHeard` (добавлен `.slice(-3)`) и нового `renderHeader`. Стилевые токены техспеки (материал/блюр/цвета) — без изменений.

## Тестирование

Новой Python-логики, которую стоило бы юнит-тестировать отдельно, не появляется — вся ветвящаяся логика (`_state_json`, `agenda_row`, `_primary_match`) уже покрыта тестами «второго экрана» и переиспользуется как есть. Проверка:
- Регрессия: полный прогон существующего набора тестов (83 теста) — `run_column.py` не должен его сломать.
- Ручная/визуальная: `column.html`, поданный через `python3 -m http.server`, прогнан через Playwright с реальными состояниями `_state_json` на разных шагах реального реплея (`fixtures/sample_daily_transcript.json` + `match_core.match()`) — проверить обрезку «Слышу» до 3 реплик, текст шапки на всех трёх фазах, тревожную строку.
- Живой прогон `run_column.py` в pywebview-окне — как для «Полосы»/«второго экрана» (безопасным способом, без полноэкранного `screencapture`).

## Не входит в этот заход

- Живой микрофон / реальный Jira-токен / диаризация.
- Гейт PRD (3-4 живых дейлика с ручным подсчётом) — по-прежнему не пройден, упирается в организационный разговор с заказчиком.
