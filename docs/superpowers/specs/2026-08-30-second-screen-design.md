# Второй экран (шаг 3) — design

## Что строим

Шаг 3 по порядку Рината («Колонка и второй экран. Те же данные, другая вёрстка — по шаблонам») — конкретно «второй экран»: широкое размещение с тремя полными колонками, в отличие от урезанной «Полосы» (шаг 2, уже сдан). «Колонка» (третье физическое размещение) в этот заход не входит — тот же принцип, другая вёрстка, отдельный заход при необходимости.

Как и «Полоса», это заход на реплее уже готового `fixtures/sample_daily_transcript.json` (не расширяем — 6 реплик уже дают и «Обсудили» (4 задачи), и «Осталось»/«Не обсудили» (2 задачи), достаточно для содержательного показа всех секций). Живой микрофон и реальный Jira — не в этом заходе.

## Что нового по сравнению с «Полосой»

«Полоса» рендерила урезанное подмножество уже готового `Meeting`. «Второй экран» показывает то же состояние **полностью** — большая часть данных уже есть, просто не рендерилась. Два реальных пробела в существующем коде, которые this iteration закрывает:

### 1. `match_core.py` — `hit_words` (было сознательно отложено при сборке «Полосы»)

Техспека: «слова заголовка подчёркнуты пунктиром» + инлайн-тег «→ SITE-12412» рядом с говорящим — оба относятся только к колонке «Слышу», не к «Записал».

`MatchResult` получает новое поле `hit_words: list[str]`:
- для `explicit_number` — сама найденная цифровая последовательность (например `"412"`);
- для `title_words` — оригинальные слова реплики (не леммы), чьи леммы совпали с заголовком задачи, без повторов, в порядке появления.

`score_task()` не меняется (её сигнатуру используют существующие тесты `test_score_task_*`). Новая приватная `_hit_words(tokens, lemmas, title_lemmas) -> list[str]` вызывается только внутри `match()` для итогового результата — zip уже вычисленных `_tokenize(utterance)` и `utterance_lemmas` (порядок сохраняется, подтверждено тестами `lemmatize.py`).

Инлайн-тег «→ KEY» не требует нового поля — это просто `Line.who` + `Line.task` (ключ, не заголовок), оба уже существуют.

### 2. `facts.py` — публичный `age_label` + новая `agenda_row`

`_age_label` (приватная) становится публичной `age_label(updated_at, now) -> str` — один источник правды для формата «обновлено N дней назад», используется и в `build_facts`, и в новой функции.

`agenda_row(task: Task, is_alarm: bool, now: datetime | None = None) -> tuple[str, str | None]` — компактная строка повестки (не карточка текущей задачи): возвращает `(f"{task.status} · {task.assignee} · {age_label(...)}", annotation)`, где `annotation` — `"задачу открыли повторно"` если `is_alarm and task.status == REOPENED_STATUS`, иначе `None` (тревога от «≥4 дня без обновления» не имеет отдельной аннотации в реальном макете — только явно переоткрытая; при рендере тревожная строка в любом случае красная, аннотация — только для случая переоткрытия). `is_alarm` сравнивается вызывающим кодом с результатом уже существующего `agenda.pick_alarm(agenda)` — сам `agenda_row` не знает про повестку целиком, только про одну задачу.

## Три колонки

Порядок слева направо, как в техспеке и в реальном макете: **Слышу | Записал | Подсказываю**.

### Слышу

Полный скролл реплик (не последняя строка, как в «Полосе»). Каждая реплика: говорящий (маленький серый лейбл) + текст. Если по этой реплике узнали задачу — говорящий получает суффикс «→ KEY», и слова из `hit_words` в тексте реплики подчёркнуты пунктиром (`text-decoration: underline dotted`).

### Записал

Зависит от `meeting.phase`:
- `before` — единый список «Повестка», без разделения на секции (задач ещё не обсуждали).
- `live` — «Обсудили» (задачи из `meeting.done`, в порядке узнавания) сверху, «Осталось» (остальные задачи повестки) снизу.
- `after` — «Обсудили» не переименовывается и не пропадает; вторая секция переименовывается в «Не обсудили».

Каждая строка — `agenda_row()`: заголовок+ключ на первой строке, `agenda_row()`'s первый элемент кортежа на второй. Тревожная задача (`agenda.pick_alarm(agenda)`, вычисляется один раз для всей повестки, не пересчитывается по фазам) — единственная строка с `color: var(--alarm)` вместо `var(--dim)`/`var(--ink)`, плюс аннотация третьей строкой если применимо.

### Подсказываю

Для `meeting.current` (если `None` — заглушка «Подсказка появится, когда узнаю задачу», как в «Полосе»):
- заголовок задачи;
- «В Jira» — **все 5** строк `facts.build_facts()` (не только первая, как в «Полосе»);
- «Сказали» — прогрессивный список: `meeting.said` (уже растёт по одной через существующий, но пока нигде не используемый `reveal_next_said()` — здесь наконец появляется реальный потребитель), с префиксом «–»;
- «Спроси» — `meeting.ask`, как в «Полосе».

## Реализация

`second_screen.html` + `run_second_screen.py`, по образцу уже готовой и одобренной пары `polosa.html`/`run_polosa_replay.py` — тот же pywebview-подход (`transparent=True`, авто-старт вместо кнопки, тот же паттерн пуша состояния до/после LLM-вызова, та же обработка ошибок credentials), та же обвязка вокруг `replay_driver`-подобного цикла с реальным Groq-вызовом. Размер окна — по техспеке 1100×760 (второй экран, колонки 330/гибкая/340).

Стили — те же токены техспеки + apple-design сдержанность, что уже утверждены и реализованы для «Полосы» (материал/блюр/типографика/reduced-motion) — не переизобретаются, переносятся как есть, поправка только на новую компоновку из трёх широких колонок вместо четырёх узких зон.

## Тестирование

- `match_core.py`: юнит-тесты на `_hit_words()` — число vs слова, дедуп повторов, порядок сохранён, нет ложных хитов на несовпавшую задачу.
- `facts.py`: юнит-тесты на `age_label` (уже была `_age_label`, тесты переносятся), `agenda_row` (все комбинации is_alarm × reopened/stale/normal).
- Интеграционный тест на сборку состояния для `second_screen.html` (аналог уже проверенного паттерна `_state_json`-контракта из «Полосы») — на том же `fixtures/sample_daily_transcript.json`, ожидаемые секции/тревожная строка сверены вручную с реальным поведением `agenda.pick_alarm()` на `fixtures/sprint.json`, не угаданы.
- Ручная проверка: реальный прогон `run_second_screen.py` в pywebview-окне, глазами против 8 правил поведения техспеки — включая новые для этого захода (подчёркивание, тревожная строка, прогрессивное «Сказали»).

## Не входит в этот заход

- «Колонка» (третье физическое размещение) — тот же принцип, другой шаблон, отдельный заход.
- Живой микрофон / реальный Jira-токен / диаризация — как и в «Полосе», следующая итерация.
- Расширение `fixtures/sample_daily_transcript.json` — текущих 6 реплик достаточно для всех секций.
