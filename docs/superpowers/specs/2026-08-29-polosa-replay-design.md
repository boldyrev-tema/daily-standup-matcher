# Полоса на реплее реального транскрипта — design

## Что строим

Шаг 2 по порядку Рината («Полоса») — но в этом заходе на реплее уже снятого реального транскрипта демо-дейлика 28.08 (44 реплики, тот же, что использовался для валидации среза 1), а не на живом микрофоне. Причина: живой overlay без доступа к реальному Jira-токену и без организационного разговора с Ринатом даст меньше уверенности, чем ещё один проход на настоящей речи с работающим LLM-слоем. Живой микрофон и реальный Jira — следующий заход, не этот.

LLM-слой («Сказали»/«Спроси») в этом заходе — **настоящий вызов Groq**, не заглушка: сам матчер уже проверен на синтетике и на реальном тексте, а LLM-контракт (структурированный JSON, запрет на выдумывание) ещё не проверялся вообще ни разу — самое время.

## Архитектура

Четыре новых модуля поверх уже существующих `sprint_snapshot.py`, `agenda.py`, `match_core.py`, `stopwords.py`, `lemmatize.py`:

```
replay_driver.py --(Line events, timed)--> meeting.py (Meeting state)
                                                 |
sprint_snapshot.py (Task, расширен) --> agenda.py --> match_core.py --(recognized)--> meeting.py
                                                 |
                                          facts.py (Task -> facts[])
                                                 |
                                          hints.py (Groq -> said[]/ask)
                                                 |
                                          polosa.html (читает Meeting, рендерит)
```

### `sprint_snapshot.py` — расширение `Task`

Новые опциональные поля (default `None`/`[]`), `agenda.py`/`match_core.py` их не используют:
- `priority: str | None`
- `labels: list[str]`
- `created: datetime | None`
- `url: str | None`

`age`/`ageLabel`/`alarm` из модели техспеки **не** становятся полями `Task` — они уже вычисляются на лету (`updated_at` → `ageLabel`, `pick_alarm()` из `agenda.py` → какая задача тревожная). Хранить их как отдельные поля значило бы дублировать источник истины.

### `facts.py` — новый модуль

`build_facts(task: Task, is_alarm: bool) -> list[str]` — чистая функция, ровно эти строки в этом порядке, каждая условна:
1. `"{status} · {who}"` — всегда.
2. `"Приоритет: критический"` — только если `task.priority == "критический"`.
3. `"Релиз в этом спринте"` — только если `"релиз_текущий_спринт" in task.labels`.
4. `"{ageLabel}"` (например «Обновлено вчера») — всегда, вычисляется из `task.updated_at`.
5. `"Создана {created:%d.%m}"` — только если `task.created` не `None`.

Результат — от 3 до 5 строк. Юнит-тесты на все комбинации условий.

### `meeting.py` — новый модуль

```python
@dataclass
class Line:
    t: float  # audio-time seconds since meeting start
    who: str | None  # None — диаризации в live-режиме нет (известный пробел техспеки)
    text: str
    task: str | None = None  # ключ узнанной задачи, если эта реплика — момент узнавания

@dataclass
class Meeting:
    phase: Literal["before", "live", "after"]
    lines: list[Line]
    done: list[str]  # ключи обсуждённых задач, в порядке узнавания
    current: str | None  # ключ задачи, о которой говорят сейчас
    fresh: str | None  # ключ только что узнанной (для 6-секундной подсветки маркера)
    said: list[str]  # накопленные строки LLM-выжимки для current
    said_n: int  # сколько строк said уже показано — растёт по одной, не сразу все
    ask: str | None
    elapsed_s: float
    remaining_count: int  # осталось задач в agenda, не обсуждённых
```

`hit?[]` (подсвеченные слова заголовка в реплике) из модели техспеки — **сознательно отложено**: `match_core.MatchResult` пока не отдаёт совпавшие слова наружу, только `task_key/confidence/reason`. `Line.task` фиксирует факт узнавания без списка слов. Полоса это не показывает (see «Что рисует Полоса» ниже), так что для этого захода это не блокер — фиксирую как известный пробел, не тихую недоделку.

Методы: `Meeting.add_line(line)` (только на финал реплики, партиалов в реплее нет — это готовый текст, не стрим), `Meeting.mark_recognized(key)` (двигает задачу в `done`, чистит `said`/`said_n`/`ask`, ставит `fresh`).

### `hints.py` — новый модуль, реальный Groq-вызов

Контракт дословно по техспеке: вход — реплики за последние 90с (по `Line.t`) + карточка текущей задачи (ключ, заголовок, статус, исполнитель, возраст, тревога); выход — строгий JSON `{"said": [...], "ask": "..." | null}`; `said` — до 3 строк по 60-90 знаков, каждая обязана опираться на конкретную реплику (промпт явно запрещает выдумывать, по аналогии с `quote_verification` в `meeting_copilot`); `ask` — один вопрос или `null`. Таймаут 3с — если не успели, показываем карточку без «Сказали» (не блокируем интерфейс ожиданием).

### `replay_driver.py` — новый модуль, НЕ часть плана Рината

Проигрывает 44 реальные реплики (тот же транскрипт, что в валидации среза 1) с паузой между репликами `≈0.4с × количество_слов` (грубая оценка темпа речи, без реальных таймкодов STT — их у нас нет, макет их тоже не публикует), вызывая `match()` на каждый финал и продвигая `Meeting`. Это наш собственный интерим-шаг для проверки UI+LLM без живого микрофона — при переходе на реальный STT этот модуль заменяется на подписку на события `live_copilot_poc`, самим не нужен постоянно.

### `polosa.html` + pywebview

**Полоса показывает урезанный набор данных, не всё, что есть в `Meeting`** (подтверждено скриншотом реального макета `smartly-rock-1020`, снятым в этой сессии):
- «Слышу»: только последняя реплика (`lines[-1]`), не список — сменяется полностью, без скролла.
- «Подсказываю»: заголовок текущей задачи + **первая строка `facts` (статус·исполнитель) — не все 5**.
- «Спроси»: `ask`, если есть.
- **«Сказали» на полосе не показывается вообще** — это не пробел, это то, что реально на макете (проверено live-прогоном демо до конца, блок не появился ни разу).
- Левая зона — `elapsed_s` (мм:сс) + `remaining_count` + кнопка Начать/Сначала (единственный интерактивный элемент, и только вне встречи).

Стили — токены техспеки: `page` rgba(19,18,23,.86)+blur 18px, radius 14; `line` rgba(255,255,255,.09); `ink`/`dim`/`mute` #F2F0EE/#9C97A3/#6b6672; `live` #54C77A 7px; `alarm` #E36B6B; `accent` текст #D6C8FF на rgba(139,92,246,.16), рамка rgba(139,92,246,.5), radius 10; шрифт Inter→-apple-system, 17-18/600 заголовок, 13-15/600 разделы, 13-16/400 текст, 12/500 mute-подписи.

**Restraint/motion (apple-design поверх жёстких правил техспеки, не вместо них):**
- Точка «слушаю» — мягкая непрерывная пульсация непрозрачности, цикл ~1.5-2с (не растягивать к 0.2 Гц — reduced-motion).
- Маркер «нового» (потемнение точки на 6с) — плавный opacity-переход, не пружина.
- Блюр — единым слоем на всю панель (18px+тень), никаких вложенных полупрозрачных слоёв внутри.
- Смена подписи колонки («Слышу»→имя / «Подсказываю»→«Говорят о задаче») — короткий кросс-фейд ~120-150мс, не мгновенная замена и не анимация появления новой строки (последнее запрещено спекой).
- Появление/скрытие самой панели по Начать/Сначала — единственное место с полноценной анимацией (блюр+масштаб вместе).
- Кнопки Начать/Сначала — фидбек на pointerdown, не на release.
- Трекинг шрифта: заголовок ~-0.01/-0.02em, тело ~0, мелкие подписи слегка положительный.
- `prefers-reduced-motion`/`prefers-reduced-transparency` — учтены (оверлей смотрят во время реальной рабочей встречи).

## Тестирование

- `facts.py`: юнит-тесты на все комбинации условных строк (3/4/5-строчные случаи).
- `meeting.py`: юнит-тесты на переходы состояния (`add_line`, `mark_recognized`, `said_n` растёт по одной).
- `hints.py`: юнит-тест с моком Groq-клиента (контракт/парсинг JSON, таймаут-фолбэк) — **плюс обязательный живой прогон на реальном Groq перед тем, как считать фичу готовой** (тот же урок, что уже был в `meeting_copilot`: моки не ловят проблемы промпта).
- `replay_driver.py` + `match_core` вместе: интеграционный тест на весь 44-строчный транскрипт, проверяет что `Meeting.done` совпадает с известным результатом (3 из 6, тот же список ключей, что в валидации).
- Ручная проверка: реальный прогон `polosa.html` в pywebview-окне на реплее целиком, глазами — совпадает ли с 8 правилами поведения техспеки.

## Не входит в этот заход

- Живой микрофон / Speechmatics-стрим (следующий заход).
- Реальный Jira-токен / `snapshot.py` HTTP-вариант (синтетическая повестка остаётся).
- `hit_words` / подчёркивание слов в транскрипте (см. `meeting.py` выше — отложено сознательно).
- Диаризация (`Line.who` остаётся `None` в live-режиме, реплей может подставлять реальные имена из демо для собственной проверки, но это не то же самое, что диаризация).
- Колонка и второй экран (шаг 3 по порядку Рината).
